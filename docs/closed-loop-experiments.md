# 最小RGB抓放闭环与反馈实验

路线假设：先推进**自主仿真垒砖的单臂单块抓放**，不是替用户选定最终赛项。现有装配离线记分器保留；内部观测/动作/日志契约可由独立装配策略复用，但尚未实现工具旋入控制。

当前可执行的是 `synthetic_rgb_kinematic`：我们编写的**合成RGB运动学场景**。没有LBot关节/碰撞/接触物理，没有O6手模型，不属于替代物理仿真、真实官方仿真或真机反馈。控制器实际从保存的RGB像素做检测和三角测量；场景隐藏物体位置只用于渲染与合成动态，不送入策略。

## 已实现的实验路径

`RGB→来源/时间/编码/校准检查→颜色连通域→两路针孔相机三角测量→显式路点→抓取后视觉确认→搬运→释放/撤手→连续3秒视觉稳定→结果与逐帧证据→回放/批量诊断`。

- 观测门只接受明确配置的RGB、校准ID和机器人末端反馈。未知顶层/嵌套字段、物体pose/TF、错误生产者/校准、非rgb8、损坏像素、过期/重复/乱序时间、不同步相机均拒绝。字段/来源配置检查不能识别被生产者伪装的真值，实际官方接入仍需审查数据来路。
- 视觉输入是真正生成的160×120 RGB字节，不是场景返回的物体坐标。检测不足或多义时等待新图像，不制造目标。当前只支持一个可见彩色块和两路已校准RGB，未完成四路相机目标关联或十块堆叠。
- 先抬高、再水平搬运、再下降；低高度水平移动及越出配置工作区被拒绝。这个检查只约束本实验路点，不能证明官方SDK关节插补轨迹、肘姿或碰撞安全。
- 动作“complete”仅代表本后端动作结束，抓手闭合/释放还必须通过RGB后验确认。没有假造手反馈、力控或官方SDK方法。
- 空抓/滑落重新观察桌面后重抓；释放粘连先返回放置点再释放；放置漂移重置稳定窗口并重新定位。持续故障受实验时钟与独立墙钟期限约束，不靠任意重试次数停止，也不无限盲重试。
- 传感器/动作传输错误、动作失败/超时、观测完整性故障均记录失败并请求停止。`stop_request_succeeded`只表示内部停止请求调用成功，`physical_stop_verified=false`明确没有物理停止证明。真实适配器必须提供有界返回和经核实的取消/停止机制；当前同步契约不能中断一个永不返回的未知SDK调用。
- 3秒是连续新帧观察窗口；遮挡/位移会重置。实验目标25mm、稳定15mm等阈值是合成实验配置，**不构成官方几何判分器**。结果固定`official_platform=false, official_score=null`。

内部`Backend.observe/submit/status/stop`等名称定义在我们的Python Protocol，**不是官方平台API**。CLI当前没有official或real执行选项，未创建伪成功的官方适配器。真实SDK/模板与合法话题确定后才能实现该边界，见[平台接入交接](platform-access.md)。

## 可复现命令

仓库根目录，Python3.10+，实验运行不需要第三方库：

```bash
python -m hand_competition.closed_loop preflight
python -m hand_competition.closed_loop run --scenario nominal --seed 0 --output runs/my-nominal
python -m hand_competition.closed_loop replay runs/my-nominal
python -m hand_competition.closed_loop batch --seeds 0 1 2 --output runs/my-batch
python scripts/check.py
```

输出目录必须不存在，防止覆盖既有结果；换新目录可重跑。`batch`默认14个场景，包含正常、临时故障和必须停止的负例；这些不是同分布比赛试次，不把混合总成功率当竞技胜率。`--without-recovery`用于对照。

拿到经授权导出的实际模板后，可先只读审查：

```bash
python -m hand_competition.closed_loop preflight --template /path/to/exported/agent_system
```

它只扫描Python AST和依赖文件、记录文件散列/导入/实体操控与TF警示，不导入执行下载代码，不读取隐藏目录或.env。`official_origin_verified=false`保留：静态工具不能证明官方来源或完整安全。已核实方法才可映射进适配器，不能把内部协议名作为官方签名。

## 输入、动作与证据格式

每个试次保存：

| 文件 | 内容 |
|---|---|
| `manifest.json` | 反馈类型、后端/场景/种子、Python/主机、相机内外参来源、配置、Git提交与dirty状态、Python模块SHA-256、复现命令 |
| `frames/*.ppm` | 每次接受的原始RGB，独立文件散列；不把物体真值分割图作为输入 |
| `events.jsonl` | 观测时间/序号/来源、图像路径/哈希、本体反馈、视觉估计、动作ID/目标/状态、阶段、故障、恢复、稳定窗口和停止请求 |
| `result.json` | 成功/失败类别、恢复次数、耗时、连续稳定时长及最终视觉估计，官方成绩始终null |
| 批量`summary.json` | 所有试次及分场景统计；失败保留，恢复中的事件数与试次成功数分开 |

运行中检测Python模块源文件变更，要求启动新进程，避免同一批次版本标识混杂。哈希链不是签名/不可篡改证明；回放重新加载RGB、执行观测门与视觉算法，并核对成功记录是否有抓取和连续稳定图像证据。它不会重放机器人动作，也不能证明原始相机来自官方平台。非法观测原始字段不落盘，避免把真值/潜在敏感数据写进日志；拒绝事件只保留错误类型，回放不复原被拒绝的原包。

原始图像、日志放在Git忽略的`runs/`；仓库仅保存小型验证摘要与复现说明，见[反馈证据](evidence/closed-loop-validation.json)。

## 诊断与改进经过

先运行不恢复对照，再启用闭环恢复。观察到：空抓与滑落虽然命令完成，但RGB高度未跟随抬升；粘连块随撤手上升；放置漂移破坏静置窗口。针对这四类状态增加重新观测后的恢复，而不是将命令返回值改成成功。

批量日志还暴露两处工程问题：无恢复路径将同一个故障在检测和终止时重复计数；版本检测从错误目录查询Git，导致提交号缺失。已去重、修正仓库定位并加回归测试。回放进一步校验连续稳定图像，拒绝只改success标签却缺少证据的记录。最终对照在冻结代码上重新运行，旧草稿结果不用于当前验证摘要。
