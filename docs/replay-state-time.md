## 独立状态与同次尝试的证据

新增`path_replay.py`，不调用Controller。它从重建RGB、本体反馈、已完成动作和恢复事实逐事件更新状态：

```text
初始/可重试 → 抬高 → 抓点上方 → 抓点下降 → close → lift
            → 同次抬升与邻近证明 → 目标高位 → 端点持有证明
            → 目标下降 → 端点持有证明 → 正常release → retreat
            → 同次放置的连续稳定 → stop → result
```

单独的动作类型白名单仍保留，但不再充当合法路径证明。正常释放与空抓重置属于不同状态；前次close/lift不能为下一次重试供证。规定路点还核对安全高度、抓点XY连续性、目标高位/下降/撤手位置。`grasp_verified`标签不是转移依据，删除标签不能破坏真实事实，矛盾标签也不能被认可。

恢复分支根据当前RGB事实开放：接近期间目标变动允许重新接近；未抬升且仍在桌面的空抓允许reset后重试；放置偏移允许重抓；撤手后块仍随手则允许重新放置。恢复编号/配置/类别/当前阶段一并检查。稳定重开不会单独授权重抓。

搬运每个接收样本都核验：单帧使用可见3D与末端距离；多帧使用颜色、像素跟随、捕获覆盖，端点再核保守3D持有界。失视/失跟随/非法观测后只允许记录当前动作状态（控制器先记录一次状态再判携带失败）、终止及停止；不允许继续下降、释放或新观测循环。`trial_stopped`和停止事件都是不可恢复终局，稳定成功后也不再接收动作。

## 四种时间分别保存

实时观测包仍为schema2；新实验manifest为schema4。接受观测的事件时间为**单调接收/后端执行时间**，payload另存：

| 时间 | 用途 |
|---|---|
| `event.time_s` / `payload.received_s` | 包送达并通过检查的时刻；事件排序和源样本年龄检查 |
| `payload.packet_time_s` | 原始观测包的time_s；严格递增、不能来自未来，不改写 |
| 每相机`captured_s` | 真实原RGB捕获时刻/序号；同步与连续稳定 |
| 本体`captured_s` | 缓存的本体测量时刻/序号；测量年龄、同步与到位证据 |

稳定时长仍累计最早传感器捕获时间。抬升/端点多帧证据根据完成反馈之后的观测序号绑定，避免将“捕获时刻须晚于回执”误用到合法缓存帧。提交动作与返回status后也检查源反馈年龄，不只检查回执新鲜。

历史v1–v3无接收字段时只能保留原证据能力，返回`receipt_timestamps_recorded=false`。新Controller搭配旧容器格式的Trace也会写两个时间字段，并可回放；旧的N1损坏日志缺接收时间，不能事后改标时间掩盖问题。

## 失败证据与验证标志

超时终止保存`deadline`：试次/动作作用域、对应action_id（动作时限）、后端耗时和相对墙钟耗时。回放核对失败时刻、请求时刻、相应预算与未完成动作；不能借晚到result的时间为较早失败证明超时。墙钟测试使用确定性的本地伪时钟，不进行长时间sleep。

只有开始、超时文字、停止和失败结果，且没有可重建依据时，哈希与终局结构可一致，但`failure_reason_reconstructed=false`、`control_record_consistent=false`，并返回限制说明。未保存的非法status或传输异常内容也不凭类型文字认作完整原因重建。成功仍须全部图像/路径/稳定条件同时通过；非法路径直接拒绝，不能通过降低标志继续宣称成功。

`trace_verified`表示文件、哈希和结构通过；`legal_path_reconstructed`表示合法路径前缀；`control_record_consistent`还要求成功事实或失败依据。所有标志均是**记录一致性**；源数据、时钟和物理执行真实性仍未认证。
