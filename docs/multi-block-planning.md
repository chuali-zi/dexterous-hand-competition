# 多块RGB关联、任务依赖与重规划

2026-10-13，在固定362e9a8单块基线通过独立验收后，按用户恢复的自主推进授权新增本阶段。目标是补上垒砖的多物体决策瓶颈：区分同色散料、在观测块体满足依赖与接触几何假设时建议上层任务、缺失支撑时重新计算依赖。0de824e首次独立审查发现三类候选误放行；[后续修复](multi-block-review-fixes.md)在固定86e12ae的[独立复验](evidence/multi-block-independent-review.md)中获范围内关闭。全部是纯离线只读规划，**没有多块机器人执行、正式判分或物理稳定证明**。官方事实继续引用[规则矩阵](rules-matrix.md)，本阶段未重新读取官方原件或更新赛况。

## 实现与输入

新增包`hand_competition/multi_block`，与已验收的单块控制器分开。沿用v2观测输入门、颜色分类与已审查针孔几何；修复后单独提取组件轮廓/面积/边界，保留微小组件。规划记录现采用独立schema2容器，不冒称旧v5动作回放。旧schema1记录属于0de824e历史，当前入口明确拒绝，须用原SHA重现。生产输入只有两个已标定相机的`rgb8`、来源/序列/捕获时间及独立时间戳的机器人末端位置；不接收物体pose、TF物体真值、隐藏编号、SetEntityPose或attach/detach。

| 模块 | 行为与拒绝条件 |
|---|---|
| perception | 只在离线完整11×11矩形色标假设下做两视图唯一双射；轮廓/面积/边界不符、歧义或数量不符保留未知障碍证据，范围保守覆盖整个工作区。无关颜色仍可跟踪，但规划候选全部等待 |
| tracking | ID仅是当前RGB连续性的本地编号。近邻有歧义时退役相关颜色；失视或时间断层退役，重现新建ID，不沿用旧完成/抓持事实 |
| planning | 配置生成4–3–2–1颜色与双下层支撑依赖；当前像素、中心、颜色连续不变至少3秒且手离开才作为几何观察证据。任一支撑缺失，所有依赖后代失效 |
| geometry constraints | 按实际观测中心计算支撑足迹并集、顶面接触高度、最终体积交叠和下降柱；支撑ID也检查穿入。散料整块在供料区域且不拥挤；幸存上层挡住下层时不建议穿越修复 |
| session | 复用输入新鲜度、序列、来源、尺寸和时差门；输入异常或300秒预算到达后不可恢复。`execute_candidate()`明确抛出未实现异常 |
| records | 保存原RGB、捕获/接收时间、派生轨迹/候选和哈希链，回放重新运行生产规划器比较。只允许观察/停止/结果，不接受动作或分数事件 |

3秒门是严格的**采样观测不变**，比原单块门更保守；不是物理静止结论。未知噪声不平均、不缩小置信区间。旧单块定位/逐帧稳定及独立路径回放代码未修改。

## 假设配置与推荐含义

[配置](../configs/multi-block.json)中的50mm立方体、60mm水平节距、5mm余量、8mm目标门、70%支撑足迹比例、供料/搭建区域及基点全部是**示例夹具假设**，不是正式场景参数、官方容差或接触稳定模型。配置禁止声明`official_scene_confirmed=true`。官方20/15mm条件不被复制成判分器；8mm仅是该离线示例的更窄候选筛选门。

8mm邻近门不能授权顶面穿入或替代实际足迹检查。新的1e-9m数值epsilon只用于浮点接触等式，不是传感器误差容差；高度不符立即拒绝，等待不会改善该几何假设。完整11×11色标也是显式离线假设，不是实物立方体的投影模型，更不是物理完整或双视图对应真实性证明。

候选按底层到顶层、同层从左至右；只建议目标颜色，支撑已缺失的结构不继续向上。错误颜色占位、下降柱障碍、模糊同色匹配或不稳定像素都会阻塞。返回`geometrically_supported_slots`只是几何依赖集合，**不能计作基础分、形状分、颜色分或合法搬运**。`official_score=null`，`robot_actions_executed=0`，执行/物理支撑/机器人碰撞/搬运来源验证标志为false。

这仍支持“先可靠自主基础抓放，再形状和颜色”的比赛路线，但当前规划器专门验证形状/颜色依赖，尚未实现基础分保分模式、结构拆除、遮挡主动换视角、双臂调度、抓姿/可达性/轨迹与机器人碰撞判断。可见块体代理没有覆盖看不见的障碍，候选不能直接转换为机器人命令。

## 验证设计与诚实限制

夹具在评估侧独立写出针孔投影方程和4–3–2–1目标坐标，未调用生产`Camera.project/ray`或目标生成函数。隐藏标签只用于选定预先写好的RGB快照，绝不进入观测包。阶段切换**不是机器人搬运的效果模型**，不能把“底层→两层→完整目标”照片序列当作已执行的堆叠。

专项测试覆盖：解析点恢复、相机/检测顺序不变、同色双射/时间近邻歧义拒绝、失视ID退役、像素/位置变化重置见证、错误颜色与区域足迹、拥挤供料、障碍下降柱、时间与终止、重算/重哈希伪造。独立依赖oracle遍历全部1024种目标块存在子集，验证递归支撑闭包；这是理想观测上的逻辑检查，不是RGB或物理成功率。

开发样例的种子0/17/101已用于定位问题，不能重新称留出集。之后冻结生产规划参数，预先选择种子207/509、不同相机基线/焦距，做两个**供料观察限定**的新夹具；它们不验证叠层泛化，也不代表真实标定误差。逐试次计数、代码/夹具/配置指纹及失败摘要见[机器记录](evidence/multi-block-validation.json)。

**以下保留0de824e修复前历史扫描**：7组、672组双相机观测，记录重算一致，机器人动作0，官方分数null。该次一致性回放没有发现MB1–MB3，不能称为算法正确性验收。当前修复后重跑及独立反例结果见[新记录](evidence/multi-block-review-validation.json)。下面是历史各阶段最后一帧结果；前三种子结果相同，不能据此推断概率：

| 快照 | 可见跟踪数 / 几何依赖有效数 | 候选或限制 |
|---|---|---|
| 开发供料 | 10 / 0 | 红色底层第1个目标 |
| 开发底层 | 10 / 4 | 黄色第2层第1个目标 |
| 开发两层 | 10 / 1 | 质心/深度偏移，依赖不足，无候选 |
| 开发完整目标 | 6 / 0 | 红色两视图数量不符，无目标完成认证 |
| 开发分支移除 | 10 / 1 | 支撑、遮挡与下降柱限制，无修复候选 |
| 单视图红色失视→重现 | 10→6→10 / 0 | 失视无红块候选；重现新ID，重新观察满3秒后有候选 |
| 1px抖动供料 | 最后一帧1 / 0 | 两视图匹配/连续像素门拒绝，全程无候选 |
| 新供料种子207/509 | 各10 / 0 | 两种相机标定配置均有红色底层候选 |

RGB连通域质心并不总是块中心。叠层相互遮挡会裁掉一视图的颜色区域，造成错误深度，即使射线残差小也可能匹配。修复仅在完整矩形色标假设内拒绝裁剪；不同物体产生相同完整色标仍不可认证。完整目标快照也出现同色数量不符。保留拒绝与失败，不放宽门限或改图片来追回“十块完成”。真实立方体表面、纹理、光照、相机畸变、标定误差、碰撞和接触均未建模；这批11×11色标实验只用于接口、关联及决策诊断。

回放报告的`record_verified`表示RGB到规划输出重算与容器一致。**它复用生产算法，不是算法正确性的独立复验**；独立解析/闭包断言与父任务后续审查须另列。拒绝事件未保存非法原包，因此回放不重建拒绝原因。来源真实性、接触支撑、动作执行、成绩均未验证。

## 复现与后续

Python标准库即可，无第三方安装、模型权重或训练：

```bash
python -m unittest discover -s tests -p test_multi_block.py -v
python -m hand_competition.multi_block blueprint configs/multi-block.json
python scripts/multi_block_validation.py --output runs/new-multi-block-scan
python -m hand_competition.multi_block replay runs/new-multi-block-scan/progress-seed-0
python scripts/check.py
```

完整RGB日志留在Git忽略的`runs/`，可由冻结源码重建；提交的是代码、参数和机器摘要。本阶段独立审查已通过。后续[接入准备核验](readiness-stop.md)确认现有执行入口拒绝条件候选，下一项有用的实际适配需要真实场景/模板资料；不以虚拟任务链代替真实反馈。官方平台、真机、付费资源和正式作品提交仍在既有授权边界之外。
