# 垒砖 RGB 接入（2026-10-17）

用户本轮同意按有相机的方案推进，随后明确告知相机使用已得到许可确认。以下记录开发副本实测；不扩展为深度、点云或物体真值使用许可。

## 场景与相机

在已有「华北五省大学生机器人大赛 - 垒砖砌筑 副本」的固定底座零件上添加 `base_cam`。没有移动砖块或修改碰撞、质量、摩擦。配置来源见 [rabokit-camera.json](../configs/rabokit-camera.json)，可按其中参数恢复：

- 父零件：`base/r6ef2dc_link_57d50b5359`；相对安装位置 `(0.65, 0, 1.4)` m。
- 原生相机 X/Y 轴：`(1, 0, 0)` / `(0, 1, 0)`；固定俯视。
- 最终图像：320×240，垂直视场角 35°，5 Hz；深度与点云关闭。640×480 曾用于细节检查，因传输问题没有作为最终连续采集配置。
- 相对话题：`base/base_cam/image_raw`、`base/base_cam/camera_info`。

这些是手动安装参数，**不是已经验证的 `T_base_camera` 标定结果**。相机 optical 坐标与原生相机轴约定要区分；机器人 SDK 控制参考系仍需核对。

## 已实现与复现

[采集脚本](../scripts/rabokit_camera.py) 只订阅当前仿真命名空间下明确指定的 RGB 与 CameraInfo，配对时间戳和 frame_id 一致的消息，检查编码、尺寸和针孔内参，保存 `frame.png`、`frame.ppm` 与 `camera.json`。记录使用仿真消息时间戳；等待采用有界的墙钟时间。实际发布端为 RELIABLE，最终脚本使用相同可靠性与深度 5。没有 SDK 或运动调用。

```bash
python competition/scripts/rabokit_camera.py \
  --topic base/base_cam/image_raw --output runs/brick-camera-01

python competition/scripts/rabokit_bricks.py runs/brick-camera-01
```

输出目录必须是新目录。脚本依赖云端已有 ROS；PNG 写入和颜色检测不需要另外安装图像库。

[砖块检测脚本](../scripts/rabokit_bricks.py) 复用已有连通区域提取，先以高饱和主色排除木纹和深色文字，再筛选足够大且近方形的候选。贴边、细长或合并区域单独列为拒绝项。该检测器适用于当前固定俯视场景，输出像素中心和边界，不输出机械臂目标，也不证明抓取成功。

## 实测

- `/tmp/brick-hand-frames-01`：SDK 默认阻塞张手返回 False，日志为到位超时、静止误差约 0.128 rad，程序退出 1。初版异常将 False 写成了「命令拒绝」，实际日志只能确定等待未成功，不能确定指令未发送。
