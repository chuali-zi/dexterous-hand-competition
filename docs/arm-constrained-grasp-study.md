# 从臂关节约束生成接触，再验证承重

日期：2026-10-25，第74轮本地研究。接续[双接触推倾与承重研究](two-contact-study.md)。本轮不访问或唤醒Rabokit。

前轮低位挡靠能维持约20°倾斜，但桌面仍承担几乎全部重量；直接升40 mm没有使整砖离桌。等高双食指的小预载也没有离桌。本轮先处理两个实际问题：接触姿态必须有相应机械臂路线；存在接触必须进一步验证负载，而不能直接视为夹持。

模型仍为 `runs/bimanual-contact-68/local-calibrated-contact.xml`，未改质量、摩擦、接触参数、根weld或手部伺服。0.1 kg质量和完整机械臂动力学仍未经原生验证。SDK只直接导入本机缓存的数值FK，没有初始化机器人或ROS。

## 候选生成结果

### 低位挡靠：有连续路线，但关节余量不足

从66轮右手插入时的实测SDK关节作为唯一初值，变量为7个右臂关节和2个食指关节；每次求值由 `SDK FK @ tool_to_hand` 得到手根。限位取SDK与配置的交集。

- 右食指末节在目标−X面形成+X法向接触，实际高度9.770 mm、穿透0.250 mm，全手最低离桌5.535 mm。
- 左手原下降和20°圆弧的58个姿态没有非目标碰撞。
- 固定朝向升高40 mm的16个2.5 mm段，以及逆向退出40 mm再升高80 mm的48段均通过数值检查；四分之一关节插值点没有手/桌/邻砖/双手障碍接触。
- 但右J2在路线中贴配置上限+0.05 rad，最小余量接近零。未借SDK较宽的+0.07 rad上限放宽配置。

单次拟合达到120次评估预算，优化器状态不是正式收敛；上述结论来自实际返回关节的接触、FK和碰撞查询。没有把它运行成新的动力学抓取，也没有验证整臂碰撞或从当前原生状态接入。

数据：`runs/arm-feasible-74/stopper/{candidate,fit,routes}.json`。

### 等高双侧拟合：保留有效右侧，排除左侧碰撞解

从66轮闭指SDK种子同时求两侧臂与食指关节，选择X方向以避开+Y邻砖。初次24次评估后，只增加一次针对左侧闲置指碰撞的修正，35次评估。

右食指能在目标−X面中心附近形成接触，点误差0.125 mm、穿透0.055 mm，全手离桌8.754 mm，臂关节余量0.209 rad。左侧接触点仍偏离12.927 mm，中指与邻砖6及目标上缘仍有约0.8–1.3 mm穿透。因此没有继续运行这个无效双侧起点。

这是有限求解的失败，不证明等高对夹整体不可行。随后复用右侧有效解，搭配已有的左侧高位食指，避免重复修补该左侧构型。

### 不同高度双侧组合

左手复用72轮高位食指，右手复用本轮有效半侧；实际接触高度分别为42.503 / 25.121 mm，法向分别−X / +X。初始只有两侧食指末节接触目标，全手最低离桌分别37.531 / 8.754 mm。

两手共同升高40 mm的SDK路线及33个实际FK姿态检查通过。右侧最小路线余量约0.215 rad；左侧复用之前已通过的同朝向路线。每侧向内2、4、6、8、10 mm的单一局部分支均通过SDK和非目标碰撞检查，名义目标接触只允许两侧食指末节。

仍需区分几何和夹持：在未加载路线的首个1.25 mm插值点，右根约0.098 mm的位置偏差及0.000379 rad姿态偏差，使原仅0.055 mm的名义重叠变成约0.0096 mm间隙。这不是物体位姿查询错误，而是很薄的名义接触无法保证沿关节插值保持。动态加载结果必须独立验证。

数据：`runs/arm-feasible-74/opposition/`。

最大10 mm/侧加载端点后的固定朝向升40 mm也通过：两臂各8段，33个组合FK采样无非目标碰撞；臂限位余量左≥0.202 / 右≥0.164 rad。检查范围仍不包含整臂碰撞及原生起点接入。

## 有界加载实测：法向力足够大，仍未承重

不同高度组合只做一个10 mm/侧加载条件：从高处下降、侧向接近后，以2 mm/s向内加载至上限，静置0.5秒，共同升40 mm用时2秒，再保持3秒。根参考和手指伺服参数均未改变。

两侧法向力峰值约3.373 / 3.801 N，已明显高于前轮小预载。因此这次不能再把失败简化为夹力不足。抬升前8.5秒，左指竖直力约−0.866 N，右指约+0.907 N，桌面约+0.948 N，砖已倾斜而大部分重量仍由桌面承担。整个试验两手向上合力采样最大仅0.7052 N，低于假定重量0.981 N。

- 40 mm抬升后，150/150个保持采样仍由桌面支撑，两手加载接触均为0。
- 左右手根实际分别升39.979 / 40.002 mm；目标质心相对抬升前下降5.486 mm。
- 保持最低角离桌−0.033817 mm；全程最低角的最大值仅0.0536 mm，未形成可接受的离桌状态。
- 左/右最后加载采样约9.58 / 9.96秒。未记录到手与桌面、邻砖或彼此的接触；邻砖初始沉降后的位移小于1.5e−12 mm。

结果为明确负例 `local_lift_hold_pass=false`。保持期间相对位置漂移小是因为砖和空手都已静止，不可单独解释成抓稳。

数据：`runs/arm-feasible-74/dynamic/fixed-ramp-10mm.json`。首次相同条件执行在结果序列化时遇到NumPy整数类型错误，没有得到可用报告；修复类型转换后原条件重跑成功。有效动态循环墙钟5.281秒；两次完整命令墙钟合计约16.184秒，含导入和写出，不能只报后一轮成本。

## 唯一等高对照也失败，停止双食指预载调参

根据前一条件的实际接触高度差，只把右手根升高17.382186 mm，保持两手XY、朝向、全部指形、10 mm预载和整个时间表不变。实际两接触高度为42.502858 / 42.502847 mm。右侧沿已解的+15 mm支路连续到新起点，再检查内移10 mm与加载后升40 mm；全部通过，加载升高路线的关节余量左≥0.20247 / 右≥0.18215 rad。没有搜索其他高度或换种子。

实际动力学仍失败：

| 左/右法向力峰值 | 3.373 / 3.801 N | 4.178 / 4.236 N |
| 两手向上合力峰值 | 0.7052 N | 0.6559 N |
| 保持最低角离桌 | −0.033817 mm | −0.033817 mm |
| 保持时桌面支撑采样 | 150/150 | 150/150 |
| 保持时左右加载接触比例 | 均0 | 均0 |
| 结果 | 未离桌保持 | 未离桌保持 |

等高条件的接触随手向上滑动并到达砖上缘，约9秒左指竖向作用转为向下，之后脱离；左/右最后加载采样为9.22 / 9.40秒。动态还发生了左右拇指末节接触，最大穿透0.0858 mm，进一步说明名义手形和FK碰撞查询不能覆盖加载后的实际柔顺姿态。没有因穿透较浅而把它写成无碰撞；通过判据也明确排除此接触。

等高回放循环墙钟5.343秒，完整命令约8.202秒。本轮两个条件、三次动态执行（其中一次输出失败）的完整命令墙钟合计约24.386秒，几何、IK、分析另计；平台唤醒0次、原生仿真0次。未修改接触或摩擦参数，也没有继续加预载、换抬升速度或微调该双食指姿态。

当前证据支持“实际向上载荷未建立、接触滑出有效侧面”，不支持“法向力再大一点就会成功”。本地接触的切向响应尚未用原生滑动记录校准，不能从这两个负例断言真实硬件没有承重能力。下一轮转向增加真实接触点或形成底面支承，重新验证可进入性与离桌保持；不会用更多同类双指参数掩盖上述负例。

输入及数值检查：`runs/arm-feasible-74/opposition/equal-high-contact-{candidate,checks}.json`。动态：`runs/arm-feasible-74/dynamic/equal-height-ramp-10mm.json`；对照图：同目录 `lift-outcomes.png`。

## 本体反馈的可用范围

用末节固定名义接触点、计划法向与模型关节雅可比，将执行器effort扣除重力并计入阻尼后投影到 `Jᵀn`，可以得到准静态法向负载提示。它不是独立力传感器，也不能忽略切向力、接触点漂移、关节限位和惯性。

复用73轮记录验证：原慢速推倾保持时，左/右法向提示相对接触真值的平均绝对误差约0.00143 / 0.00850 N；进入抬升滑动阶段后扩大至0.0447 / 0.1068 N。即使分析中提供真实接触力矩、接触点和法向，纯法向投影仍会混入切向载荷。右手当时的软限位力矩较小，不能把它写成该保持段误差的主要原因。

新组合的右侧 `Jᵀn` 范数只有约7.26 mm，左侧约76.5 mm，不能沿用旧姿态的估计精度。上述加载实测在8.5秒右侧真实法向力约3.536 N时，投影提示却约−4.877 N，直接证明该标量不适合作为停止夹紧或已承重的条件。因此本轮在运行前已取消双侧估计力阈值控制，使用固定上限加载；本体反馈和投影只记录，不影响运动。

论文中的多模态反馈在这里应落实为：RGB确认对象和位移，本体反馈识别受阻、脱离、速度异常，力学模型解释这些信号可能对应哪些接触；最终仍以完整离桌和保持验证。不能把两个相关PD量当成两种独立触觉，也不能把单方向投影扩展成完整接触力。

反馈分析：`runs/arm-feasible-74/stopper/loading-feedback.json`。

## 两个求解失败的解释得到纠正

原双侧左手约π姿态差的端点求解受到旋转向量分支切口影响。保持原种子、目标、限位和评估上限，仅将大姿态端点残差换为旋转矩阵差，15次评估获得满足原FK阈值的解，关节余量0.1443 rad。这证明原端点失败不能被写成物理不可达；没有因此声称从初值到端点存在连续路线。

原推倾末态继续上升的+10→15 mm段，拆成两个2.5 mm段后均通过。两段最大关节变化0.085409 / 0.073563 rad，合计0.158972 rad超过旧单段局部搜索边界。失败包含步长因素，不能只归因于真实限位；同时J6仍贴真实上限，鲁棒余量问题并未消失。

[路径代码](../scripts/rabokit_joint_path.py)新增显式的 `refine_once=True` 选项，默认关闭。仅当原段IK返回无解时增加一次中点，子段禁止再次细分；原关节步长、FK和插值检查保持。原段成功时不增加求解。合并逻辑保留总关节变化超过0.15 rad的两个半段。

[相关测试](../tests/test_rabokit_joint_path.py)覆盖有效中点恢复和真实限位仍失败。joint_path 15项、bimanual_route 2项通过；原+10→15 mm反例通过实际生产入口，终点误差约6.44e−10 m / 3.20e−8 rad。未把这次局部恢复扩展解释为整条40 mm路线通过。

数值记录：`runs/arm-feasible-74/solver/`。完整机械臂碰撞体、原生承重、搬运、放置和正式得分仍未验证。

本轮生产代码仅新增默认关闭的单次中点细分选项；17项相关回归、修改Python语法、本文件及前轮记录的本地链接和Git差异检查通过。动态负例与输出失败分别保留，不计作抓取成功。没有为同步记录而唤醒平台。
