# 第二接触反力、直接承重与机械臂可达性

2026-10-25，第73轮；起始提交 `3518c11`。承接[薄指入口与推倾研究](pregrasp-access-study.md)，本轮检验另一只手能否限制底边滑移，并独立检查双手直接侧夹。所有动态均在本地原模型进行，没有访问或唤醒Rabokit。

**得到一个可维持约2秒倾斜开口的双接触预操作，但直接抬升失败，当前机械臂数值路线也未完整成立。** 该结果支持“需要独立反力”的判断，仍不构成抓稳方案。

## 低位挡靠确实改善了推倾

右食指在目标−X下侧、桌面上约10 mm提供挡靠，左手沿上一轮相同20°圆弧推倾。首次竖直右手与左手下降/圆弧有明显交叠，未运行动态；唯一几何修正将右手向−X外倾45°，保持低位接触点与指形，使掌部退出左手扫掠区域。修正后右手最低静态桌面间隙7.277 mm，两手从无接触的高处/侧方进入。

原模型保持假定质量0.1 kg、50 mm砖、μ=1、防滑迭代0、原接触/驱动参数及9块可动邻砖。目标未预先移动或倾斜，控制动作只依赖固定时间表，物体状态仅用于离线评价。模型仍缺少完整机械臂动力学、已校准的有效质量和原生碰撞网格。

| 保持约2秒的实测量 | 结果 |
|---|---:|
| 实际砖倾角 | 20.058–21.680° |
| +X自由底边开口 | 17.088–18.405 mm |
| 左/右食指加载接触采样 | 各50/50 |
| 原−X底边的X位置偏移 | +0.674至+1.771 mm |
| 砖最低角点离桌 | −0.0667至−0.0601 mm，仍接触桌面 |
| 左/右实际接触高度 | 约57–58 / 9.55–10.04 mm |

上一轮单手圆弧最大开口时，底边向−X漂移约8 mm；加入低位挡靠后，开口可以维持。该比较保留相同左手圆弧和原物理设置，改善来自增加的实际手部接触。没有双手互撞、手碰桌面或手碰邻砖。邻砖初始自然沉降后的三维变化小于5.2e−12 mm，不能把含沉降的初始到末尾位移混称为扰动。

保留[双接触条件输入](../configs/two-contact-pregrasp-local.json)。它明确标为本地预操作，且双手都已占用；不能假定另有一只手可以把上一轮薄指入口直接接上。

## 相同接触直接抬升：失败

确认保持末态双侧仍加载后，只增加一次承重对照：保持手形、接触顺序及物理参数不变，两手根共同升40 mm用时2秒，再保持3秒，没有增加预载。对照开始抬升前的338行状态与原预操作记录完全一致。

- 实际左/右手根分别升39.996/40.002 mm，但整砖最低角点没有一次完整离桌；抬升阶段采样最大值仍为−0.0102 mm。
- 最后双侧加载接触采样为13.88秒，首次两侧均无接触为13.92秒。只定位到40 ms采样区间，不声称知道更精确的失持先后。
- 失持前两指向上合力采样最大约0.664 N，低于假定砖重0.981 N，剩余载荷仍由桌面承担。
- 随后75/75个保持采样的最低角点均约−0.033817 mm，双侧加载接触均为0/75；最终相对左/右手漂移约48.965/49.445 mm。

没有继续增大预载或改变抬升速度。结果分别保留在 `runs/two-contact-73/stopper/dynamic.json` 与 `dynamic-lift.json`，原记录未覆盖。

## 承重分析：稳定倾斜不等于手在承重

只读分析原保持末态13.48秒，使用该步缓存的13.478秒接触力，排除桌面后复用现有重力平衡分析。

| 量 | 数值 |
|---|---:|
| 左/右实际接触法向力 | 0.4563 / 0.4881 N |
| 双手向上合力 | 0.01295 N |
| 桌面向上反力 | 0.96799 N |
| 双手/桌面对质心Y向力矩 | −0.01449 / +0.01449 N·m |
| 实测法向预算下，圆摩擦锥允许的竖向力上界 | 0.88928 N，仍低于砖重 |

因此当前法向预算本身就不够，不能只靠“两个手指都受阻”判断能抬起。仅考虑净力平衡的共同每侧法向预算必要下界约0.63701 N，不含力矩、执行器和控制误差。假设1 N/侧时，净力可以平衡，最小力矩残差约5.41e−6 N·m；精确三维两点LP仍因微小非共面不可行。这是点接触模型限制，不能据此断言柔顺接触永远无法承重。1 N是分析假设，没有被当作已执行力指令或原生手部力限。

## 独立双手等高侧夹也没有离桌

另比较单食指与食指+中指两种几何代表。两手各向外展开15°后，高处下降80 mm、侧向接近10 mm的采样路径无碰撞。单食指只做一次0.5 mm/侧根位置预载，再抬40 mm、保持3秒。

两手确实各升约40 mm，砖留桌。左右法向力峰值仅0.0888/0.0942 N，向上合力峰值0.1318 N；保持时均无目标接触。第二种指形在相同预载下中指仍距目标0.347 mm，并没有增加真实接触，因此未重复动态。

这不能说明原生双手力能力不足：稳态根平移误差只有0.0103 mm，但根角度误差约0.144°，在约170 mm杠杆上可对应0.43 mm位移，可能吸收了大部分小预载。模型的根约束不能替代完整机械臂。这里分别隔离weld等式约束，经约束雅可比转置计算其广义力，避免把全部接触约束力混称为根驱动力；[MuJoCo官方API](https://mujoco.readthedocs.io/en/3.3.7/APIreference/APIfunctions.html#mj-muljactvec)明确该变换的含义。峰值weld力约1.648/1.672 N只描述模型，不验证原生力限。

## 机械臂约束需要提前进入候选生成

数值检查仅直接导入本机缓存SDK的FK函数，限位取SDK与配置交集。没有创建机器人、ROS连接或平台动作。存在解、连续路线与碰撞验证分别记录。

- **纠正上一轮左侧失败的解释：** 72轮左pusher低位有精确端点解，从该解同朝向升80 mm的16个局部段满足FK/限位/插值阈值。此前从native66种子直接连接高位失败，不等于该末端姿态不存在。
- **72轮右薄指入口：** 两个有记录来源的种子都能求得低位解，但当前分支到+20 mm时J2/J5碰限位，不能给出80 mm高处入口路线。
- **本轮挡靠方案左侧：** 从已解低位沿实际弧/保持样本18段均通过数值验收，最小限位余量约0.03186 rad；继续同朝向升高只通过+5/+10 mm，第+15 mm段受J6真实上限和J5局部步长边界影响，40 mm路线未完成。
- **本轮挡靠方案右侧：** 一次有依据种子的低位求解未通过，J2/J5触配置上限，残余位置/姿态误差约60.11 mm/0.50453 rad。没有继续扩大种子搜索。

这些有限求解不证明所有肘姿都不可达；优化器达到评估上限的记录也保留，数值通过只按返回关节的FK和限位判断。失败的双侧夹持左姿态另有约π旋转差造成的求解退化，不将数值问题写成物理不可达。

下一阶段候选直接从SDK限位内的机械臂关节与手指构型生成，同时检查实际接触、桌面/邻砖/双手间隙以及负载升高路径。先避免出现可用的浮动手几何，却没有对应机械臂路线的情况，再以短动力学验证承重。当前预操作用于保留接触模式，不能直接部署。
